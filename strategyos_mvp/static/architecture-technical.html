Technical architecture

Governed intelligence, enforced end to end.

StrategyOS combines deterministic business logic, evidence-grounded retrieval and bounded AI workflows. Identity, tenant, authority, review and effect controls are enforced server-side across the same runtime.

Deployment model

Containerised Python/FastAPI application with persistent relational, graph, vector, object and queue services. The public edge exposes only the authenticated application boundary.

Request lifecycle

One enforcement sequence

A browser request, assistant question or agent tool call cannot bypass the server-side trust boundary.

Authenticate

Resolve the session at the trusted edge and establish tenant, subject and product role. Hosted surfaces fail closed without a valid identity.

Authorise

Classify the information domain and required right, then resolve the effective authority row and policy version before retrieval.

Retrieve

Select only permitted run state, evidence, graph relationships and semantic context. Preserve source and citation identifiers.

Compute

Run deterministic calculations and detectors. Models may explain results, but they do not manufacture KPI truth.

Review

Pause governed publication or consequential work when evidence, approval or authority is incomplete.

Execute safely

Verify capability scope, approval state, idempotency and effect keys before any tool handler performs a consequential effect.

Audit

Persist the request, evidence, policy decision, review, result and execution state so every visible status has a source of truth.

Data and state

Different stores, one governed run

Each storage service answers a different technical question; the run identifier and tenant boundary keep their projections coherent.

PostgreSQL · transactional truth

Runs, checkpoints, approvals, policies, tasks, audit events and publication state.

Object storage · evidence artifacts

Source files, extracted artifacts and generated outputs with stable addresses.

Neo4j · relationship truth

Entities, KPI/value-driver structure, ownership, source lineage and cross-domain relationships.

Qdrant · semantic retrieval

Vector search over approved evidence and context, filtered by the active tenant and governed run.

Operations and resilience

Deploy, observe, recover

The runtime is packaged as a portable container stack and verified at both dependency and user-surface boundaries.

Authenticated public edge

TLS terminates at the edge; application and data services remain private. Production is designed for customer OIDC and non-root deployment.

Health and readiness

Liveness is separate from authenticated readiness checks for database, graph, object, OCR, identity and governed runtime dependencies.

Observable workflows

Run jobs, checkpoints, worker events, review state and agent execution logs expose operational state without exposing hidden reasoning.

Recoverable state

Persistent stores and evidence artifacts are backed up and restored independently; deployment rollback does not erase governed data.

✓
The architectural invariant

Every business claim, access decision and consequential effect must be traceable to a governed run, a policy decision and a persisted record. The interface is a projection of that state—not a parallel source of truth.
